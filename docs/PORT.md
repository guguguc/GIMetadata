# 跨版本常量搬运（`tools/port.py`）—— 实测报告与边界

> 目标：把"换版本还要人工抄 200 个常量"变成"自动搬"。
> **结论先说**：**部分成功，但不能单独信任**。已验证 6/6，但字段密钥 0/4 ✗。

## 一、思路

同一程序换代，**代码结构几乎不变**，变的是常量。`sig.py` 能定位 48~54 个函数，于是：

```
同一个函数 -> 指令序列对齐(difflib) -> 对齐到同一位置的指令
          -> 比较立即数/位移 -> 得到 old -> new 的映射
```

相比"搜候选 + 结构自证"，位置本身带语义（同一位置 = 同一字段/表/key）。

## 二、实测（7.1 -> 7.0）

```
旧版定位 54 函数，新版 48，共同 48
对齐指令对 184651；48/48 函数相似度 >=80%
常量映射：8520 个 old 值有 new 值；64 个冲突
```

| 项 | 结果 |
|---|---|
| 字符串密钥 `keyMulA/B/Seed/Step` | **4/4 ✅**（票数 3~9，置信 1.00） |
| `fieldDefaultValues` key | **✅** `0x593DE464 -> 0x720EB389` |
| `fieldAndParameterDefaultValueData` key | **✅** `0x3F525210 -> 0x26AB5EF8` |
| `fieldDecode.typeDef.*` | **0/4 ✗**（与 `slot_scan --struct` 候选全不一致） |
| 小常量（slot/位移，如 `0xB4`） | **不可用** ✗（同一个 0x10/0x18 满二进制都是） |

## 三、为什么字段密钥会错

1. **内联**：字段读取被内联到几十个地方，同一个 `add reg,imm` 形状到处都有；
   对齐只看"形状"，会把 A 字段的 key 对到 B 字段的位置上 ✗
2. **编码形态会变**：7.1 `xor rcx, 0x4A4C0A71` 在 7.0 变成 `mov ecx,0x...; add ecx,reg`
   → 对齐对不上，**什么方法都搬不了**（只能靠语义反查）
3. **补码**：`sub K` 常被写成 `add -K`（32/64 位宽度还不一致）

实测反例：`typeDef.methodStart` 被"搬"成 `0xBD37EABA`，
而 `--struct` 显示该值属于 **`+0x24 nameIndex`** ✗ —— 说明对齐错位。

## 四、能用的部分（已验证）

- 字符串密钥 4 个 ✅（也可以直接用 `sig.py consts`，更可靠）
- 结构自证表的 **key**（fDV / blob）✅ —— 但这两张 ⑦ 反查本来就能给 ✓

**所以 port 目前的净收益 ≈ 0**：能搬的，别的工具也能给；搬不了的，它也不可靠。

## 五、什么情况下值得再用

- 目标是**同一个函数的同一处代码、且编码形态不变**的常量
- 必须配**独立验证**（结构自证 / 语义不变量 / 输出侧统计）才能采信

## 六、要真正提高自动化率，方向是

| 方向 | 预期收益 | 难度 |
|---|---|---|
| **语义不变量**（累计索引单调 / 连续性校验） | 中（能覆盖 typeDefs + 依赖它的表） | 中 |
| **候选召回**（`--anchor` / 更多指令形态 / 调用图扩散） | 高（是当前最大瓶颈） | 中 |
| **无密钥反解**（哨兵 raw 反推 key） | 高（`CROSS70 §六` 已在 7.1 验证） | 中 |
| **指令对齐** | 低（本报告已证伪其对字段密钥的有效性） | — |
| 纯结构探针 | 已到极限（5 张表） | — |
